# Stage 11 maps

`lib/maps/locations.ts` validates source identity, WGS84 coordinate ranges, paired nulls, dates, duplicate IDs and exact correspondence with the official published map link. `catalogAt(asOf)` layers applicable coordinates onto the immutable base catalog, appending dated sources and two claims per known pair. Maps are not a dependency for property admission: malformed optional bundles are withheld at runtime, while `npm run validate:maps` blocks CI. The foundation and catalog CLI share current ingestion; Stage 9 historical audits retain their original dated base. No prior factual/editorial record is changed.

`lib/maps/geography.ts` reads the ordinary effective evidence view and derives property/trip stops, preserving unknowns, conflicts, staleness and repeat visits. It owns finite Mercator projection, short-span antimeridian fitting, capped zoom, visible tiles and consecutive itinerary segments. It never changes trips, scoring, pricing, profiles or watch targets. Lines use geographic context, not actual transport routes or dates; a missing stop breaks both adjacent segments. Dateline segments that would span the long side of a world view are omitted rather than drawn misleadingly.

`MapPanel` keeps the location list outside a lazy renderer, loading state and error boundary. Details show one property; comparison shows the selected 2–4; trip geography shows the active trip's ordered stays, even with incomplete or invalid quote drafts. Changes to stay order/property rebuild the map with new numbering. Choosing the focus selector centers a stop, including colocated visits; fit restores all locations. Zoom and cardinal pan buttons support keyboard use without a drag-only interaction. No device geolocation.

`GeographicMap` fetches the base-aware, hashed local Natural Earth asset only after Show geographic map. Its strict asset schema rejects malformed land data. Network/HTTP/parse errors and 10-second timeout show a recovery message beside the still-visible list; Retry map refetches. Unmount cancels the fetch without an error update. The React error boundary contains renderer/module failures, with Retry map and Reload page. Failed ES module imports can remain cached by the browser; Reload page is the reliable chunk recovery path. The existing valid saved planner is retained.

Street maps load only after Load street map, centered on the selected published pin. Visible raster tiles use standard HTTPS `tile.openstreetmap.org/{z}/{x}/{y}.png` requests, wrapped x and bounded y, with normal browser cache/Referer behavior. Image errors or a 12-second incomplete-tile timeout discard the street overlay and restore fit geographic context; Retry street map is deliberate. They do not block lists, totals or saving. No bulk or offline tile download. OSM is a replaceable optional map provider, not a dynamic Marriott-data provider.

No schema migration is needed: v1 saved planners and v2 profile/trips/watchlist backups are unchanged, and map controls do not trigger repository writes. Backups reconstruct geography from stable property IDs and current sourced coordinates rather than embed duplicate geodata. Every source date and confidence remains inspectable through latitude/longitude evidence in property details.
